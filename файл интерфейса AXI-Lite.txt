Это нужно прописывать в файле **`SEGAGamePad_slave_lite_v1_0_S00_AXI.v`** (файл интерфейса AXI-Lite, который автоматически сгенерировал Vivado, когда вы создавали IP-ядро).

Ниже — подробная инструкция с конкретными номерами строк (ориентировочными, так как Vivado может добавлять пустые строки) и готовым кодом, который нужно вставить.

### Шаг 1. Откройте нужный файл
В дереве проекта (`Sources` -> `Design Sources`) разверните ваш IP-блок и дважды кликните по файлу **`SEGAGamePad_slave_lite_v1_0_S00_AXI.v`**. Именно в нем находится вся логика обмена данными с процессором по шине AXI.

### Шаг 2. Добавьте пользовательские порты (входы/выходы)
В самом начале файла, в секции объявления портов (примерно строки **10–15**), найдите комментарий `// Users to add ports here`. Вставьте туда следующие строки:

```verilog
    // Users to add ports here
    input  wire [31:0] gp_status,   // Вход: состояние кнопок из логического модуля
    output wire        polling,     // Выход: сигнал включения автоопроса (в логический модуль)
    output wire        select,      // Выход: сигнал ручного управления Select (в логический модуль)
    output wire        interrupt,   // Выход: сигнал прерывания на процессор
    // User ports ends
```
*(Обратите внимание: `gp_status` — это вход для этого файла, потому что данные приходят из вашего модуля логики. А `polling`, `select`, `interrupt` — выходы, потому что процессор задает их через регистры, а логика их читает).*

### Шаг 3. Добавьте логику связи регистров (в конце файла)
Прокрутите файл почти до самого конца, найдите комментарий **`// Add user logic here`** (примерно строка **300**). **Вставьте туда следующий код**:

```verilog
// Add user logic here

    // --------------------------------------------------------
    // 1. Регистр VERSION (0x00) — только чтение
    // --------------------------------------------------------
    // Мы жестко задаем версию ядра, например 1.
    // (Здесь нельзя использовать always @(posedge S_AXI_ACLK) с неблокирующим присваиванием 
    // для константы, проще использовать assign, но так как это регистр, оставим как в примере)
    always @(posedge S_AXI_ACLK) begin
        if (S_AXI_ARESETN == 1'b0)
            slv_reg0 <= 32'h0000_0001; // Версия 1
        else
            slv_reg0 <= 32'h0000_0001; // Всегда 1
    end

    // --------------------------------------------------------
    // 2. Регистр CONTROL (0x04) — управление
    // --------------------------------------------------------
    // Бит 0 (EN) - разрешение работы (можно использовать для сброса логики)
    // Бит 1 (P)  - непрерывный опрос (polling)
    // Бит 2 (SL) - ручное управление Select (select)
    // Бит 3 (IE) - разрешение прерываний
    
    assign polling = slv_reg1[1] & slv_reg1[0]; // Опрос работает только если EN=1 и P=1
    assign select  = slv_reg1[2] & slv_reg1[0]; // Ручной Select работает только если EN=1 и SL=1

    // --------------------------------------------------------
    // 3. Регистр STATUS (0x08) — только чтение (состояние кнопок)
    // --------------------------------------------------------
    // Просто передаем состояние кнопок из логического модуля в регистр.
    always @(posedge S_AXI_ACLK) begin
        if (S_AXI_ARESETN == 1'b0)
            slv_reg2 <= 32'h0000_0000;
        else
            slv_reg2 <= gp_status;
    end

    // --------------------------------------------------------
    // 4. Регистр INTERRUPT (0x0C) — прерывания (W1C)
    // --------------------------------------------------------
    // Это упрощенная реализация. Полноценную логику прерываний (детекторы фронта) 
    // вам нужно будет написать самостоятельно, если это дополнительное задание.
    // Здесь мы просто разрешаем прерывание, если установлен бит IE (slv_reg1[3]).
    
    assign interrupt = slv_reg3[0] & slv_reg1[3]; // Прерывание идет, если есть флаг и разрешено

// User logic ends
```

### Шаг 4. Уберите старый код записи для slv_reg0 и slv_reg2 (Важно!)
В сгенерированном файле (примерно строки **150–200**) есть большой блок `always @(posedge S_AXI_ACLK)`, который описывает, как процессор **записывает** данные во все 4 регистра. 

Вам нужно **найти и удалить (или закомментировать `//`)** куски кода, которые отвечают за запись в `slv_reg0` и `slv_reg2`. Потому что:
*   `slv_reg0` (VERSION) — только для чтения, в него нельзя писать.
*   `slv_reg2` (STATUS) — только для чтения, в него пишет только ваша логика, а не процессор.

Оставьте логику записи только для `slv_reg1` (CONTROL) и `slv_reg3` (INTERRUPT).

### Шаг 5. Свяжите модули в файле верхнего уровня (`SEGAGamePad.v`)
Теперь вам нужно соединить проводами порты из `..._S00_AXI.v` и порты из вашего логического модуля `SEGAGamePad_logic.v`. 
Откройте файл **`SEGAGamePad.v`** (он самый верхний в иерархии).

1.  **В объявлении портов верхнего уровня** (там же, где вы добавляли `gp_...`) вам нужно добавить выходные порты для прерывания (если будете делать) или просто убедиться, что все сигналы объявлены.
2.  **Внутри модуля** (там, где инстанцируются `..._S00_AXI` и `SEGAGamePad_logic`) вам нужно соединить их между собой. 

Примерно это должно выглядеть так:

```verilog
    // Внутренние провода для связи AXI-интерфейса и логики
    wire [31:0] gp_status_wire;
    wire        polling_wire;
    wire        select_wire;
    wire        interrupt_wire;

    // 1. Инстанцирование логического модуля (того самого, что вы писали по Листингу 6)
    SEGAGamePad_logic #(
        .DELAY_US_TICKS(150) // 150 МГц -> 150 тактов на 1 мкс
    ) gamepad_logic_inst (
        .clk           (S_AXI_ACLK),     // Тактирование от AXI
        .rst_n         (S_AXI_ARESETN),  // Сброс от AXI
        .polling       (polling_wire),   // Приходит из AXI
        .select        (select_wire),    // Приходит из AXI
        .gp_up_z       (gp_up_z),        // Физические пины (порты верхнего уровня)
        .gp_down_y     (gp_down_y),
        .gp_left_x     (gp_left_x),
        .gp_right_mode (gp_right_mode),
        .gp_c_start    (gp_c_start),
        .gp_b_a        (gp_b_a),
        .gp_sel        (gp_sel),         // Физический выход на геймпад
        .gp_status     (gp_status_wire)  // Уходит в AXI
    );

    // 2. Инстанцирование AXI-интерфейса (Vivado сгенерировал это автоматически, 
    // вам нужно просто добавить новые порты в его список подключений)
    SEGAGamePad_slave_lite_v1_0_S00_AXI #(
        // ... параметры ...
    ) SEGAGamePad_slave_lite_v1_0_S00_AXI_inst (
        // ... стандартные AXI порты (S_AXI_ACLK, S_AXI_ARESETN и т.д.) ...
        
        // ДОБАВИТЬ ВОТ ЭТИ СТРОКИ:
        .gp_status     (gp_status_wire),   // Сюда приходит статус из логики
        .polling       (polling_wire),     // Отсюда уходит в логику
        .select        (select_wire),      // Отсюда уходит в логику
        .interrupt     (interrupt_wire)    // (Опционально) в процессор
    );
```

### Резюме
1.  В файле AXI (`..._S00_AXI.v`) вы прописываете, как читать/писать регистры.
2.  В файле логики (`SEGAGamePad_logic.v`) вы описываете работу со счетчиками и кнопками.
3.  В файле верхнего уровня (`SEGAGamePad.v`) вы **соединяете** их проводами.

После этого можно нажимать **Run Synthesis**. Если Vivado не ругается на синтаксис — значит, вы всё сделали правильно, и можно упаковывать IP-ядро и добавлять его в основной Block Design.
